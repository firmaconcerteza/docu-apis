Flujo backend

El flujo esperado es simple:

PasoAccionEndpoint
1Registrar que un usuario monitorea una entidadPOST /api/monitoreos
2Cuando otro servicio encuentra algo, enviar el evento con la entidad relacionadaPOST /api/eventos
3Consultar pendientes para mostrar avisosGET /api/notificaciones/{usuario_id}?estado=PENDIENTE
4Al abrir o atender una notificacion, marcarla como leidaPATCH /api/notificaciones/{notificacion_id}/leida

Si una notificacion se marca como LEIDA, ya no sale cuando se consulta con estado=PENDIENTE. Para verla despues, consultar sin filtro de estado o con estado=LEIDA.

Monitoreos

POST/api/monitoreos crea o reactiva un monitoreo. Es idempotente.

VS Code .http
### Crear o reactivar monitoreo
POST http://161.35.107.123:3011/api/monitoreos
Content-Type: application/json
x-api-key: a9087485730ed01568457f3ab620a2f0cfbc10aaca2a0be3

{
  "usuario_id": "8bc0bd7c-b7f0-586f-8c69-db0bb9c4e900",
  "entidad_id": "8bc0bd7c-b7f0-586f-8c69-db0bb9c4e900"
}

GET/api/monitoreos/{usuario_id}?estado=activo lista lo que monitorea el usuario.

VS Code .http
### Listar monitoreos activos
GET http://161.35.107.123:3011/api/monitoreos/8bc0bd7c-b7f0-586f-8c69-db0bb9c4e900?estado=activo
x-api-key: a9087485730ed01568457f3ab620a2f0cfbc10aaca2a0be3

DELETE/api/monitoreos/{usuario_id}/{entidad_id} inactiva el monitoreo.

VS Code .http
### Desactivar monitoreo
DELETE http://161.35.107.123:3011/api/monitoreos/8bc0bd7c-b7f0-586f-8c69-db0bb9c4e900/8bc0bd7c-b7f0-586f-8c69-db0bb9c4e900
x-api-key: a9087485730ed01568457f3ab620a2f0cfbc10aaca2a0be3

Eventos encontrados

POST/api/eventos lo usan los servicios internos cuando detectan un juicio u otro evento relacionado con entidades. Si la entidad esta monitoreada, se crea una notificacion.

VS Code .http
### Reportar evento encontrado
POST http://161.35.107.123:3011/api/eventos
Content-Type: application/json
x-internal-token: 902ecb99fb30acea7e23c7525fac0a2cdb77201e08211fd3

{
  "event_id": "evento-juicio-20260927-002",
  "tipo_evento": "juicio",
  "id_evento_publico": "juicio-20260927-002",
  "fuente": "iva-judicial",
  "fecha_evento": "2026-09-27T18:00:00Z",
  "entidades": [
    {
      "id": "8bc0bd7c-b7f0-586f-8c69-db0bb9c4e900",
      "rol": "demandado"
    }
  ],
  "metadata": {
    "numero_expediente": "EXP-2026-002",
    "juzgado": "Juzgado Civil",
    "descripcion": "Se registro un juicio relacionado con la entidad monitoreada"
  }
}

event_id debe ser unico. Si se manda dos veces el mismo event_id, el servicio responde correctamente pero no duplica la notificacion.

Marcar como leida

PATCH/api/notificaciones/{notificacion_id}/leida cambia la notificacion a LEIDA y establece fecha_lectura.

VS Code .http
### Marcar notificacion como leida
PATCH http://161.35.107.123:3011/api/notificaciones/6a0c38d6-f4b0-4c11-b416-97ddd101d3bf/leida
x-api-key: a9087485730ed01568457f3ab620a2f0cfbc10aaca2a0be3

PATCH/api/notificaciones/leidas marca varias en una sola llamada.

VS Code .http
### Marcar varias notificaciones como leidas
PATCH http://161.35.107.123:3011/api/notificaciones/leidas
Content-Type: application/json
x-api-key: a9087485730ed01568457f3ab620a2f0cfbc10aaca2a0be3

{
  "usuario_id": "8bc0bd7c-b7f0-586f-8c69-db0bb9c4e900",
  "notificacion_ids": [
    "6a0c38d6-f4b0-4c11-b416-97ddd101d3bf"
  ]
}

Despues de marcar como leida, esa notificacion ya no aparece en ?estado=PENDIENTE. Para confirmar el cambio se puede consultar el contador o listar con ?estado=LEIDA.

Campos importantes para backend/frontend

CampoUso
_idID de la notificacion. Se usa para marcarla como leida.
entidad_idEntidad que tuvo movimiento.
nombre_canonico_inversoNombre de la entidad obtenido desde entidades en modo lectura.
id_evento_publicoID del evento que puede abrir el frontend.
tipo_eventoTipo del evento, por ejemplo juicio.
rolRol de la entidad dentro del evento, por ejemplo demandado.
estadoPENDIENTE o LEIDA.
